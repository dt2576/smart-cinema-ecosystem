# Implementation Reports

Reports document actual implementation or repository maintenance work and its verification. They are evidence, not project requirements, and must reference actual requirement IDs and document versions when relevant. They must never silently redefine BRD/SRS.

Use [TASK_REPORT_TEMPLATE.md](templates/TASK_REPORT_TEMPLATE.md) and name reports `YYYY-MM-DD_<task-name>_report.md`. Preserve old reports; never overwrite an existing file. Use a distinct task-name suffix if needed.

Record checks honestly, including NOT RUN and its reason. Requirement reconciliation uses PASS, PARTIAL, FAIL, or NOT APPLICABLE. Do not invent requirement IDs for work that has no business requirement mapping.
